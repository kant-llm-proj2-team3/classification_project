# 프로젝트 기본 데이터

프로젝트를 시작할 때 사용할 기본 데이터입니다. 고객 문의 분류와 답변 초안, 문서 분류와 요약 중 선택한 주제의 폴더를 사용하세요.

## 파일 안내

data/inquiries는 고객 문의, data/documents는 문서 데이터입니다. 두 주제를 모두 수행할 필요는 없습니다. 각 폴더에 아래 파일 6개가 있습니다.

| 파일 | 주제별 수량 | 용도 |
| --- | --- | --- |
| `labels.json` | 라벨 3개 | 라벨 설명과 숫자로 바꿀 때의 순서 |
| `train.csv` | 360행 | 분류 모델 학습 |
| `validation.csv` | 120행 | 모델 선택과 개선 과정의 확인 |
| `test.csv` | 120행 | 모델과 조건을 정한 뒤 최종 평가 |
| `generation_development.jsonl` | 15건 | 생성 기능과 프롬프트 개발 |
| `generation_eval.jsonl` | 24건 | 로컬 생성 모델과 상용 생성 모델의 최종 비교 |

## 데이터 읽기

CSV는 한 행이 한 사례입니다. UTF-8 BOM이 포함되어 있으므로 Python에서는 utf-8-sig로 읽습니다. JSON과 JSONL은 UTF-8이며, JSONL은 한 줄에 JSON 객체 하나가 있습니다.

| CSV 컬럼 | 의미 |
| --- | --- |
| text | 분류 모델에 넣을 원문 |
| label | 학습과 평가에 사용할 정답 |
| id | 사례의 고유 번호 |
| group_id | 함께 분할해야 하는 상황 묶음 |
| source | 자료 출처 |

분류 모델에는 text를 입력합니다. label과 관리용 컬럼은 입력에 넣지 않습니다. 라벨을 숫자로 바꾸면 labels.json의 labels 목록 순서를 학습과 예측에서 동일하게 사용합니다.

- 고객 문의: shipping은 배송과 수령, refund는 주문 취소와 반품 및 환불, account는 가입과 로그인, 회원정보와 계정 권한 및 자료 관리입니다.
- 문서: announcement는 대상에게 내용을 알리는 공지, manual은 작업 방법을 설명하는 매뉴얼, minutes는 진행된 논의와 결정을 기록한 회의록입니다.

특정 단어보다 문의의 주된 요청과 글의 목적을 기준으로 봅니다. 상품 주문 취소는 refund, 회원 탈퇴는 account입니다. 회의에서 정한 변경을 이용자에게 알리는 글은 announcement일 수 있습니다.

같은 상황을 다르게 표현한 두 문장을 같은 group_id로 묶었습니다. 두 문장의 라벨은 같습니다. 제공된 train, validation, test 분할을 사용하고, 새로 나눌 때도 같은 group_id를 서로 다른 분할에 넣지 않습니다. test는 학습이나 모델 선택에 사용하지 않습니다.

## 생성용 파일 읽기

text는 문의 또는 요약할 원문입니다. expected_label은 분류 정답, required_points는 응답에 필요한 내용, forbidden_claims는 응답에서 단정하면 안 되는 내용입니다. rubric_note가 있으면 평가할 때 참고합니다. id, group_id, source와 split은 자료 관리용 값이며 파일에 따라 split이 없을 수 있습니다.

정답과 평가 항목은 모델 입력에 넣지 않습니다. 서비스에서는 실제 예측 라벨을 사용하고, 생성 응답을 받은 뒤 평가 항목과 비교합니다.

제공된 고객 문의의 평가 기준은 아래 가상 서비스 정책을 전제로 합니다. 생성 모델에도 이 정책을 전달해야 합니다.

- 배송은 공식 주문 내역과 배송 지원 경로에서 확인하도록 안내합니다. 실제 조회나 장소 변경을 완료한 것처럼 답하지 않습니다.
- 반품은 수령 후 7일 이내 접수하는 가상 기준입니다. 접수와 승인을 구분하고 상품 상태를 확인합니다. 기간만으로 승인이나 거절을 단정하지 않으며, 이미 접수한 건은 처리 상태를 확인하도록 안내합니다.
- 비밀번호 문제에만 실습용 상대 경로 /account/reset을 안내하고 실제 사이트 주소가 아님을 알립니다. 다른 계정 문의는 요청에 맞는 공식 계정 관리나 고객지원에서 확인하도록 합니다. 없는 기능이나 메뉴를 만들거나 대화창에서 비밀번호와 인증코드를 요구하지 않습니다.
- 날짜와 금액, 처리 완료 여부를 추측하지 않습니다. 실제 주문 조회, 환불 승인이나 계정 변경 기능은 이 데이터에 포함되어 있지 않습니다.

문서 요약은 원문을 근거로 합니다. 공지는 대상과 일정 및 예외, 매뉴얼은 조건과 순서, 회의록은 제안과 결정 및 보류를 구분합니다. 원문에 없는 사실을 덧붙이지 않습니다.

팀이 정책을 바꾸면 프롬프트와 평가 기준도 함께 맞춥니다.
